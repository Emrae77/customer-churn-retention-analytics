# Data source and preparation

## Exact dataset version

This project uses the classic IBM Telco Customer Churn CSV: **7,043 customer records and 21 original columns**. One row represents one customer. The source is a public IBM sample, not a live company feed. It should not be described as the results of a retention campaign or an analysis commissioned by a telecommunications company.

## What is in the file

| Field(s) | Meaning and handling |
| --- | --- |
| customerID | Customer key; require present and unique. |
| gender | Source demographic category. |
| SeniorCitizen | Source indicator, 0 or 1; this is not a numeric age. |
| Partner, Dependents | Yes/No source categories. |
| tenure | Months recorded with the company; retain zero-month customers. |
| PhoneService, MultipleLines | Phone service subscription. Preserve `No phone service`. |
| InternetService | DSL, Fiber optic, or No. |
| OnlineSecurity, OnlineBackup, DeviceProtection, TechSupport, StreamingTV, StreamingMovies | Service subscription categories; preserve `No internet service`. |
| Contract | Month-to-month, One year, or Two year. |
| PaperlessBilling, PaymentMethod | Billing arrangements. They do not record billing failures. |
| MonthlyCharges | Recorded monthly charge. No currency column is supplied; dashboards avoid imposing a currency. |
| TotalCharges | Recorded cumulative charges; 11 whitespace-only values become nullable numeric values. |
| Churn | Yes/No outcome label supplied by IBM. |

There are no observation dates, churn-event dates, churn reasons, geography, actual customer ages, satisfaction scores or `Joined` status in this particular file. Other Telco datasets and IBM's enhanced samples contain additional fields. Those variants are not used here.

## Cleaning decisions

1. Trim surrounding whitespace without changing the meaning of categories.
2. Reject missing or duplicate customer IDs rather than counting a customer twice.
3. Validate allowed categorical values. Preserve service absence categories; an unknown value is not automatically `No`.
4. Convert tenure, MonthlyCharges and TotalCharges to numeric fields. Reject unexpected numeric strings and invalid required values.
5. Keep 11 blank TotalCharges entries as missing. All occur in the zero-month group. They are not replaced with a measured zero and their customers remain in churn denominators.
6. Add `ChurnFlag` (Yes = 1, No = 0), `TotalChargesMissing`, `TenureBand` and `TenureBandSort`.

Tenure bands are 0 months, 1–12 months, 13–24 months, 25–48 months and 49–72 months. The separate zero-month band makes the missing-charge group visible. A band describes the customers' recorded tenure, not a calendar period or an acquisition cohort.

The reporting population is **7,043 before and after preparation**. A figure of 6,418 from a different tutorial or dataset is not used in this implementation. Known TotalCharges values are present for 7,032 customers. A calculation using those charges should disclose that denominator; a churn calculation does not require dropping the 11 other customers.
